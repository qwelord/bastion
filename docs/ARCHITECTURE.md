# Архитектура

## Решение ADR-001: локальное приложение с web-интерфейсом

React + TypeScript + Vite — общий web-клиент с адаптивной доской. Правила и модель партии вынесены в независимые TypeScript-модули для повторного использования на сайте и в мобильном приложении. Stockfish работает в браузерном Worker, native bridge для текущего этапа не нужен. Выбор упаковки мобильного приложения и аккаунты/сервер относятся к следующим этапам; установка Windows больше не является единственной целевой платформой.

## Границы

```
React views → application state → domain ports
                                  ├─ ChessRules (реализован)
                                  ├─ EngineService (игра реализована, анализ — далее)
                                  ├─ GameRepository (этап 7)
                                  └─ CurriculumRepository (этап 9)
```

В живой игре используются ChessGame, Match и StockfishClient. Текущая партия, настройки и закладки хранятся в версионированном localStorage. Это локальная тренировочная версия; серверная база и синхронизация проектируются отдельно. Сценарные данные в src/data относятся к учебному образцу анализа и каталогу, а не к компьютерному сопернику.

## ADR-002: достоверность

Ходы соперника поступают от настоящего Stockfish и повторно проверяются моделью правил. Старые ответы после смены партии, отмены или паузы отбрасываются. Штатный Elo и дополнительная учебная шкала обозначаются отдельно; рейтинг пользователя не выдумывается. Анализ сыгранных партий в отдельном экране ещё не реализован, там явно показан учебный образец.

## ADR-003: графика

Фигуры — оригинальные SVG из набора Cburnett в Lichess, без изменения содержимого. Все 12 изображений поставляются локально; ссылка на исходную ревизию и хеши находятся в public/pieces/SOURCE.json. Никаких 3D-моделей, генератора фигур или зависимости Three.js. Доска — плоская сетка однотонных полей. Лицензии и атрибуция сохранены в docs/ASSETS.md.

## ADR-004: отсутствие обязательных сетевых сервисов

Игра работает без API, аккаунта и платной модели. Шрифты поставляются локально. Будущая синхронизация и свободные объяснения опциональны. Доступ к сети не требуется для основных локальных сценариев.

## Критерии расширения

- Логика шахмат не должна находиться в React-компонентах.
- Не добавлять full backend до необходимости синхронизации.
- Функциональные изменения проверять на поведении пользователя, не на деталях реализации.
- Сохранить миграции данных, экспорт и границы лицензирования до первого публичного релиза.
